# 技术决策记录（ADR）

## ADR-0001：技术栈选择 Go + Vue 3

**状态**：已接受（建议）

**决策**：

- 后端 Go
- 前端 Vue 3 + TypeScript + Vite
- 数据 SQLite
- CUPS 作为打印引擎

**理由**：

- Go 单二进制、低资源、部署简单
- Vue 3 适合重构页面和手机端
- SQLite 对单用户足够
- 比 Django/Celery 轻，比 Flask 单体更适合长期维护

**后果**：

- 需要自己实现更多业务代码
- 但架构清晰、依赖少、长期维护成本低

## ADR-0002：单用户，无用户体系

**状态**：已接受

**决策**：

- 不做 users/login/JWT/OIDC
- 打印页局域网开放
- 管理页使用一个 `ADMIN_TOKEN`

**理由**：

- 目标是家庭/小办公室单用户
- 用户体系会显著增加复杂度
- 以后需要多人时再扩展

## ADR-0003：网页只走 PPD，本地可 PPD/RAW

**状态**：已接受

**决策**：

- 网页打印只提交 PPD 队列
- 本地客户端可以连接 PPD 或 RAW
- 一个物理打印机的一个 `printers` 记录同时保存两个队列

**理由**：

- 网页上传的文件类型不可控，PPD 队列能正确转换
- RAW 没有页码/双面/格式校验，只适合本地驱动
- 避免网页误选 raw 导致空白/连续打印

## ADR-0004：集成 CUPS，不依赖系统 CUPS

**状态**：已接受

**决策**：

- Docker 镜像内自带 CUPS
- 对外暴露 8631 IPP
- 不依赖 cups-web 或宿主系统 CUPS

**理由**：

- 部署简单、版本可控
- 避免应用中心重启覆盖配置
- 可打包分享

**后果**：

- 镜像体积较大（LibreOffice/Ghostscript）
- 需要处理 USB 挂载和 CUPS 启动

## ADR-0005：许可证采用 Apache-2.0

**状态**：已接受

**决策**：

- 采用 Apache License 2.0
- 允许商用、闭源二次开发、修改和分发，需保留版权与许可声明
- 项目根目录提供 `LICENSE`

**理由**：

- 项目定位长期分享，希望允许商用/闭源二次开发
- Apache-2.0 含专利授权条款，比 MIT 更适合
- 参考 Gutenberg（AGPL）只参考设计，不复制代码到本项目

**注意**：

- 参考 cups-web-print（GPLv3）时注意衍生作品义务
- 闭源第三方驱动（Canon CAPT/UFR2、Brother brscan4 等）不随项目分发

## ADR-0006：异步任务队列 + 双层队列

**状态**：已接受

**决策**：

- 应用层任务队列由 printd 自己维护：SQLite `jobs` + 单 worker，负责接单、格式转换、参数持久化、重试、历史
- CUPS 负责实际打印队列、过滤器链和 USB 输出
- `POST /api/print` 校验落盘后立即返回 `202 + job_id`，前端轮询状态下，不阻塞等待
- 单 worker 串行处理，天然串行化 USB 访问

**理由**：Office/图片转换不是 CUPS 职责；HTTP 不能阻塞等待转换；执行状态仍以 CUPS 为准。

## ADR-0007：打印参数按 PPD 动态生成

**状态**：已接受

**决策**：打印页参数（纸张、双面、颜色、分辨率、缩放等）从所选打印机的 PPD 选项动态读取，UI 只展示设备实际支持的项。

**理由**：Brother DCP-7060D 是黑白激光机，固定清单会显示不存在的彩色选项；不同打印机能力不同，硬编码不可维护。

## ADR-0008：P1 支持多打印机

**状态**：已接受

**决策**：P1 打印机管理、打印页选择器均支持多台打印机；每台物理打印机对应一条 `printers` 记录和 PPD + RAW 两个队列。

**理由**：设备发现可能发现多台设备；提前支持避免后续改数据模型和 UI。

## ADR-0009：扫描作为 P1 收尾项

**状态**：已接受

**决策**：扫描功能排在打印、管理主流程之后；先做扫描仪发现与网络扫描（sane-airscan），USB 扫描依赖 Brother `brscan4` 驱动；若驱动打包调试未通过，扫描顺延 P1.1，不阻塞 P1 发布。

**理由**：核心价值是打印；`brscan4` 为闭源驱动，容器内打包存在依赖和权限风险。

## ADR-0010：驱动管理采用「内置 + 驱动包 + 索引」分层

**状态**：已接受

**决策**：

- 镜像只预装开源可再分发驱动：brlaser（DCP-7060D 必需）、cups-filters；foomatic-db 仅作型号索引
- 驱动包（gutenprint、escpr、hplip、splix、foo2zjs、Canon 等）不预装，管理页按需上传安装/卸载/更新
- 驱动状态通过 PPD `*cupsFilter` 校验：`ready` / `degraded` / `missing`
- 型号索引从 `lpinfo -m` 读取并缓存，不把索引数量当作已支持
- 闭源驱动（Canon CAPT/UFR2、Brother brscan4 等）不预装，由用户上传
- 网络打印机优先 IPP Everywhere，免驱动

**理由**：避免镜像膨胀和许可证风险；避免 cups-web 式「UI 显示支持很多，实际可用要看状态表」的问题。参考 cups-web 的教训：驱动包、Foomatic 索引、状态表是三件事，不能混为一谈。
