# 技术决策记录（ADR）

## ADR-0001：技术栈选择 Go + Vue 3

**状态**：已接受（建议）

**决策**：

- 后端 Go
- 前端 Vue 3 + TypeScript + Vite
- 数据 SQLite
- CUPS 作为打印引擎

**理由**：

- Go 单二进制、低资源、部署简单
- Vue 3 适合重构页面和手机端
- SQLite 对单用户足够
- 比 Django/Celery 轻，比 Flask 单体更适合长期维护

**后果**：

- 需要自己实现更多业务代码
- 但架构清晰、依赖少、长期维护成本低

## ADR-0002：单用户，无用户体系

**状态**：已接受

**决策**：

- 不做 users/login/JWT/OIDC
- 打印页局域网开放
- 管理页使用一个 `ADMIN_TOKEN`

**理由**：

- 目标是家庭/小办公室单用户
- 用户体系会显著增加复杂度
- 以后需要多人时再扩展

## ADR-0003：网页只走 PPD，本地可 PPD/RAW

**状态**：已接受

**决策**：

- 网页打印只提交 PPD 队列
- 本地客户端可以连接 PPD 或 RAW
- 一个物理打印机的一个 `printers` 记录同时保存两个队列

**理由**：

- 网页上传的文件类型不可控，PPD 队列能正确转换
- RAW 没有页码/双面/格式校验，只适合本地驱动
- 避免网页误选 raw 导致空白/连续打印

## ADR-0004：集成 CUPS，不依赖系统 CUPS

**状态**：已接受

**决策**：

- Docker 镜像内自带 CUPS
- 对外暴露 8631 IPP
- 不依赖 cups-web 或宿主系统 CUPS

**理由**：

- 部署简单、版本可控
- 避免应用中心重启覆盖配置
- 可打包分享

**后果**：

- 镜像体积较大（LibreOffice/Ghostscript）
- 需要处理 USB 挂载和 CUPS 启动

## ADR-0005：许可证待定
