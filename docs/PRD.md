# Print Portal 产品需求文档（PRD）

- 版本：v0.1
- 状态：P1 目标已确认，待开发
- 项目：Print Portal（打印门户）
- 目标平台：fnOS NAS（Debian 12，x86_64）

## 1. 背景

现有环境是一台 fnOS NAS，通过 USB 连接 Brother DCP-7060D 打印机。过去使用第三方 `cups-web` 应用（闭源、`source=thirdparty`），存在：

- 网页打印机列表把主 PPD 队列错误映射到 raw 队列
- raw 队列暴露到公网后被扫描器不断触发，打印机一直出空白页
- 应用中心重启会重新生成 `cupsd.conf`，丢失局域网权限
- PPD 队列处理大 PostScript 文件时，`gstoraster` 的 bbox 预处理非常慢
- 打印机配置、地址修改依赖后台命令，页面化不足

因此决定自研一个长期可维护的单用户打印门户，参考开源项目的设计，但保持架构简单。

## 2. 产品目标

1. 局域网手机/电脑打开网页即可打印，不需要安装驱动
2. 管理页可配置打印机、CUPS 参数、PPD/RAW 队列，不写死地址
3. 网页打印只走 PPD 队列，避免用户误选 raw
4. 本地客户端可自由选择 PPD 或 RAW 连接
5. 内置 CUPS，不依赖系统单独安装
6. 单用户，无用户体系；管理页仅一个 `ADMIN_TOKEN`
7. 长期可分享、可扩展、可重构 UI

## 3. 用户与场景

### 主要用户

- 家庭/小办公室的单一管理员
- 局域网内的手机、平板、电脑用户

### 典型场景

1. 手机打开网页，上传 PDF/照片，直接打印
2. 选择页码范围、双面、份数
3. 管理员在网页上添加新打印机、修改 IP、选择驱动
4. Mac 本地驱动通过 RAW 队列打印大文件
5. 管理员查看 CUPS 状态、队列、任务、日志
6. 扫描仪自动发现，在网页扫描并下载 PDF

## 4. 非目标（当前阶段）

- 用户注册、登录、角色权限
- 配额、审批、审计（以后可扩展）
- 公网直接访问（只允许局域网/VPN）
- 多租户
- 邮件打印、云打印
- 移动端原生 App

## 5. 核心概念

### 物理打印机

一台实际设备，例如 `Brother DCP-7060D`，通过 USB 或网络连接。

### 打印队列

同一物理打印机可有两个队列：

- **PPD 队列**：CUPS 负责格式转换，支持页码、双面等
- **RAW 队列**：无 PPD，CUPS 原样透传，客户端负责渲染

### 打印模式

- **网页打印**：只使用 PPD 队列
- **本地 PPD**：本地客户端连接 PPD 队列
- **本地 RAW**：本地客户端连接 RAW 队列

## 6. P1 功能范围

### 6.1 打印页

- 路由：`/`
- 响应式布局：手机、平板、电脑 Chrome 共用一套页面；桌面宽屏左右分栏（预览 + 参数），手机单列
- 浏览器范围：现代 Chrome（桌面/手机），不保证其他浏览器
- 打印机选择：多打印机时显示选择器，默认选中默认打印机
- 上传：点击、拖拽、手机文件/相册；一次提交一个文件，提交后可继续提交下一个任务，任务按顺序排队
- 支持格式（P1 核心格式）：
  - PDF
  - JPEG / PNG / WebP
  - Word / Excel / PPT（LibreOffice 转 PDF）
  - PostScript（`ps2pdf` 转 PDF）
- 后续版本：HEIC / TIFF（需额外转换库）、WPS（.wps/.et/.dps）
- 文件预览：PDF 首页缩略图、图片缩略图、页数
- 打印参数：从所选打印机的 PPD 动态读取，UI 只显示设备实际支持的选项
  - 全部页 / 页码范围
  - 单面 / 双面长边 / 双面短边
  - 份数
  - 纸张大小 A4/A5/Letter
  - 方向
  - 黑白/彩色（设备支持时）
  - 缩放
- 提交方式：异步提交。点击「打印」即创建任务：上传完成返回 `job_id` 后本次交互即结束，后台任务队列负责转换和提交 CUPS；前端不阻塞等待，用户可继续操作或离开页面
- 任务进度：在任务列表/状态区查看；页面打开时轮询更新，完成时页面内提示；页面关闭则下次打开可见历史结果
- 提交后状态：
  - 待处理（pending）、转换中（converting）、已提交（submitted）、排队中（queued）、打印中（printing）、已完成（completed）、失败（failed）、已取消（cancelled）
- 操作：取消、重试
- 历史任务
- 深色模式（P1）、中文界面（P1）、英文（后续版本）；PWA 作为可选增强

### 6.2 管理首页

- 路由：`/admin`
- `ADMIN_TOKEN` 登录/验证：登录页输入 token，存 `sessionStorage`；管理请求头带 `X-Admin-Token`
- 仪表盘：
  - CUPS 版本、运行状态
  - 默认打印机
  - 打印机数量、活动任务数
  - 最近任务
  - 当前告警

### 6.3 打印机管理

- 路由：`/admin/printers`
- 打印机列表 + 每台配置卡（P1 支持多台）：
  - 名称
  - 型号/PPD
  - PPD 队列名
  - RAW 队列名
  - 设备地址 `device-uri`
  - 是否默认
  - 是否共享
  - 当前状态、队列长度
  - PPD 地址、RAW 地址、二维码
- 操作：
  - 新增/修改/删除
  - 修改设备地址（PPD/RAW 同步）
  - 修改 PPD/驱动
  - 设默认
  - 测试打印
  - 暂停/恢复、接受/拒绝任务、清空队列
- 保存时后端调用 `lpadmin`

### 6.4 设备发现/添加向导

- 入口：管理 → 打印机 → 添加打印机（三步模态向导）
- 自动发现：
  - USB：`lpinfo -v`，`usb://...`
  - 网络 IPP/AirPrint：内置 Go mDNS browser（`_ipp._tcp`、`_ipps._tcp`），不依赖 ippfind/Avahi
  - 扫描仪：mDNS `_uscan._tcp`、`_uscans._tcp`、`_scanner._tcp`
- 向导步骤：
  1. **选择设备**：打开页面默认先执行本地（USB）扫描，完成后自动执行局域网扫描；「局域网扫描」只扫描局域网 IPP/AirPrint；「扫描」扫描所有设备（局域网 + 本地/USB）；异步扫描，发现的设备动态加入列表；设备卡片展示名称、型号、URI、网络/USB 类型；支持 Standard TCP/IP (RAW/9100) 手动输入 IP + 端口；支持手动输入设备 URI（高级）
  2. **选择驱动**：按品牌/型号选择，支持搜索品牌、型号或文件名；显示可用驱动型号总数；支持上传 PPD / 压缩包 / deb 驱动；网络设备可选用 IPP Everywhere 免驱动
  3. **配置**：打印机名称、PPD/RAW 队列名、是否默认、是否共享；保存时自动创建双队列
- 添加：
  - IPP Everywhere/AirPrint → `lpadmin -m everywhere`（免驱动）
  - USB → 读取 1284DeviceID（MFG/MDL），在驱动索引中匹配 PPD
  - 匹配不到 → 型号搜索（`lpinfo -m`）或手动上传 PPD
- 驱动来源与状态检测见 6.11 驱动管理
- 默认同时创建 PPD + RAW 队列

### 6.5 扫描

- 路由：`/scan`
- P1 优先级：排在打印、管理主流程之后；先实现扫描仪发现与网络扫描（`sane-airscan`），USB 扫描需 Brother `brscan4` 驱动；若驱动打包/调试未通过，扫描顺延 P1.1，不阻塞 P1 发布
- 自动发现扫描仪
- 参数：
  - 分辨率 150/300/600 dpi
  - 彩色/灰度/黑白
  - PDF/JPEG/PNG
  - 单面/双面（设备支持时）
- 流程：扫描 → 预览 → 下载
- 技术：`scanimage -L`、`scanimage --format=pdf`、`sane-airscan`，Brother 扫描仪可加 `brscan4`

### 6.6 CUPS 控制台

- 路由：`/admin/cups`
- 状态显示：
  - CUPS 版本、ServerName
  - 监听端口
  - WebInterface、DefaultShared、Browsing
  - LogLevel、MaxJobs、MaxJobsPerPrinter
  - MaxRequestSize、PreserveJobHistory、PreserveJobFiles
  - 每个打印机的状态、状态原因、DeviceURI、MakeModel、PPD、队列、耗材
- 参数配置：
  - 上述常用参数表单
  - PPD 默认选项：PageSize、Duplex、Resolution、InputSlot、MediaType、TonerSave
- 高级：
  - `cupsd.conf` / `cups-files.conf` 文本编辑
  - 保存前 `cupsd -t` 校验
  - 自动备份、回滚、重载

### 6.7 任务管理

- 路由：`/admin/jobs`
- 活动/历史任务，合并展示两类来源：
  - **Web 任务**：来自应用队列（SQLite），有完整打印参数，可预览原文件、可重试
  - **本地直连任务**：本地客户端通过 PPD/RAW 队列直接提交，来自 CUPS；显示队列、任务标题、用户、大小、状态、时间，可取消；无法预览内容
- 本地任务同步：printd 启动时及每 5 秒从 CUPS 拉取 `lpstat -W all -o`，以 `cups_job_id` 去重写入 `jobs` 表（`source=local`）；CUPS 清理历史后本地记录仍保留
- 任务详情：
  - Web 任务：完整参数 + 原文件预览
  - 本地任务：元数据 + 状态时间线，明确提示「本地直连任务，内容由客户端直接发送，系统无法预览」
- 字段：来源（Web/本地）、打印机、文件、页数、单双面、份数、时间、状态
- 操作：取消、暂停、恢复、重试（仅 Web 任务；重试 = 新建任务，保留原失败记录）、清空历史
- P1 不开启 `PreserveJobFiles`；P2 如需排障可增加「下载原始打印流」

### 6.8 应用设置

- 路由：`/admin/settings`
- `ADMIN_TOKEN`
- Web 端口
- 上传大小
- 允许格式
- 临时文件保留
- 历史保留
- 默认打印机
- 语言/主题
- 二维码/访问地址
- 默认值：上传上限 200MB、临时文件保留 24 小时、任务历史保留 30 天

### 6.9 日志与备份

- `/admin/logs`（P1）：应用日志、CUPS error_log、任务日志
- `/healthz`：健康检查
- `/admin/backup`（P1.1）：导出/导入配置、数据库、PPD、cupsd.conf

### 6.10 部署

- 单个 Docker 容器，内置 CUPS
- 对外端口：
  - `8088`：Web
  - `8631`：CUPS/IPP（本地 PPD/RAW）
- USB 设备挂载
- CUPS 配置/spool/日志持久化
- 停用 cups-web，避免端口/USB 冲突

### 6.11 驱动管理

- 路由：`/admin/drivers`
- 驱动分层：
  - **内置驱动**：镜像自带（brlaser、cups-filters），只读，不可卸载
  - **驱动包**：可安装的第三方驱动包（gutenprint、escpr、hplip、splix、foo2zjs、Canon 等），按需上传安装/卸载/更新
  - **PPD**：手动上传的 PPD 文件
- 驱动列表：名称、版本、类型（内置/驱动包/PPD）、状态、支持型号数、许可证
- 状态检测：
  - 解析每个 PPD 的 `*cupsFilter` / `*cupsFilter2`，检查 `/usr/lib/cups/filter/` 中过滤器是否存在
  - `ready`（过滤器齐全）/ `degraded`（缺过滤器，列出缺失项）/ `missing`（无 PPD）
  - UI 必须区分「已安装可用」与「仅索引、可安装」，不能把索引型号数当作已支持
- 支持型号：
  - 直接解析 `lpinfo -m`（已聚合 foomatic/brlaser 等全部 PPD），内存缓存，支持搜索
  - 可从型号列表直接创建打印机
- 操作：
  - 上传安装驱动包（deb / tar.gz）与 PPD
  - tar.gz 驱动包结构约定：`ppd/*.ppd`、`filter/*`（可选）、`backend/*`（可选）
  - 卸载驱动包（内置除外）
  - 重新检测状态
- 驱动持久化：
  - 上传的驱动包与 PPD 存放在 `/app/data/drivers/`（持久卷）
  - 容器启动时自动重放安装并重新检测状态，重建/升级不丢
- 安装安全：上传 deb/tar.gz 需二次确认，显示包名、版本、来源；仅 `ADMIN_TOKEN` 管理员可操作
- 卸载保护：打印机正在使用该驱动的 PPD 时拒绝卸载（409），提示先更换驱动
- 默认策略：
  - 镜像只预装开源可再分发驱动（brlaser、cups-filters；foomatic-db 仅作索引）
  - 闭源驱动（Canon CAPT/UFR2、Brother brscan4 等）不预装，由用户上传
  - 驱动包安装需 `ADMIN_TOKEN`，安装前显示来源与许可证提示

### 6.12 共享

- 路由：`/admin/sharing`
- 访问地址配置：主机/IP、CUPS 端口、Web 端口（保存后所有连接信息自动更新）
- 每台打印机展示：
  - **PPD 连接地址**：`ipp://<host>:<cups_port>/printers/<ppd_queue>`，用于网页打印 / 本地 PPD 客户端
  - **RAW 连接地址**：`ipp://<host>:<cups_port>/printers/<raw_queue>`，用于本地 RAW 客户端
  - **网页打印地址**：`http://<host>:<web_port>/`
  - 复制按钮
- 每台打印机两个开关：
  - **允许访问**：由 printd 的 IPP 网关校验，关闭后局域网客户端无法通过 IPP 连接
  - **允许发现**：控制 CUPS/DNS-SD 广播，仅在允许访问开启时可设置
- CUPS 仅监听 `127.0.0.1:631`，局域网只暴露 printd IPP 网关 `8631`
- 客户端连接说明：macOS、Windows、Linux/CUPS

## 7. PPD 与 RAW 规则

- 网页：只允许 PPD 队列
- 本地 PPD：`ipp://<nas>:8631/printers/<ppd_queue>`
- 本地 RAW：`ipp://<nas>:8631/printers/<raw_queue>`
- RAW 队列不支持页码/双面/份数，UI 必须提示
- 两个队列共用 USB 时，backend 层 `flock` 串行化

## 8. 安全要求

- 只允许局域网访问，不做公网端口映射
- 打印页不需要登录
- 管理 API/页面必须 `ADMIN_TOKEN`
- 上传类型白名单、大小限制、文件名过滤
- 临时文件定期清理
- CUPS 配置修改前校验、备份、可回滚
- 不暴露 CUPS 管理密码/证书私钥到前端

## 9. P1 验收标准

1. 手机打开网页，上传一页 PDF 能正常打印
2. 电脑 Chrome 打开网页，上传 PDF、选参数、提交打印全流程可用；1280×800 与 1920×1080 下无横向滚动、无元素遮挡
3. 选择 `1-2` 页 + 双面，能只打一张纸（两页）
4. 大 PDF 能看到转换/排队状态，不会误走 raw
5. 提交打印后前端立即返回任务 ID，可继续操作或关闭页面；后台继续完成转换与打印，重新打开页面能看到任务状态
6. 网页看不到 raw 队列，也不会把主队列映射到 raw
7. 管理页能修改打印机设备地址，PPD+RAW 队列同步更新
8. 管理页能修改 PPD 默认选项并生效
9. 能暂停/恢复队列、取消任务、测试打印
10. 能显示 CUPS 版本、状态、队列、任务
11. 设备发现页能发现局域网/USB 打印机并自动创建队列
12. 扫描页能发现扫描仪并扫描 PDF（P1 收尾项；USB 扫描依赖 brscan4，未通过则顺延 P1.1）
13. 高级 CUPS 配置修改有校验、备份、回滚
14. 重启容器后配置和任务历史不丢
15. 局域网外不可访问
16. 驱动管理页能显示驱动状态（ready/degraded/missing）、搜索支持型号，能上传安装 PPD/驱动包并用于创建打印机
17. 日志页能查看应用日志、CUPS error_log 和任务日志

## 10. 后续版本

- P2：用户体系、配额、审计、公网/VPN、邮件打印、多租户
- 只有在明确需要多人分享时才引入，不进入 P1

## 11. UI/UX 设计要求

**整体目标**：好看、直观、现代、有高级感；打印页是产品门面，不能停留在脚手架占位风格。

### 设计原则

- 直观：核心路径（选文件 → 设参数 → 打印）一屏完成，不超过 3 步；状态用颜色 + 文字表达，不让用户猜
- 现代：统一设计 token（颜色、字号、间距、圆角、阴影），组件复用，不写一次性样式
- 高级：克制的配色与动效，重视留白、排版层级和细节；避免模板感
- 一致：打印页、管理页、扫描页共用同一设计系统

### 视觉规范

- 色彩：中性灰背景 + 白色卡片 + 单一强调色；语义色区分状态（成功绿、警告琥珀、失败红、信息蓝）
- 字体：系统字体栈；标题 28–32px，正文 14–16px，辅助文字 12–13px
- 间距：4/8px 栅格；卡片内边距 20–24px
- 圆角：卡片 16–20px，按钮/输入框 10–12px
- 阴影：柔和、低对比，避免重投影
- 动效：150–250ms，拖拽/上传/状态切换有反馈；尊重 `prefers-reduced-motion`

### 关键页面

- 打印页：桌面左右分栏（左预览、右参数），手机单列；拖拽上传高亮反馈；任务状态卡片清晰
- 管理页：桌面用表格，窄屏自动切卡片式列表
- 空状态、加载骨架屏、错误提示拟人化（说清原因和下一步）

### 视觉验收

- 1280/1920 桌面与 375 手机下视觉一致、无错位
- 所有交互具备 hover / focus / active / disabled 态
- 深色模式完整可用
- 原生控件（按钮、文件选择）全部定制，不出现浏览器默认样式
